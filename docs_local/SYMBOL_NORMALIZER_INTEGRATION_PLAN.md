# Symbol Normalizer Integration Plan

Status: first-stage `get_market_data` integration implemented behind a feature flag. Broader tool-layer integration is still not approved.

Date: 2026-07-05.

Update on 2026-07-07:

* Implemented only for `get_market_data`.
* Feature flag: `VIBE_TRADING_ENABLE_SYMBOL_NORMALIZER`.
* Default: off.
* Enabled values: `1`, `true`, `yes`, `on`.
* Flag-off behavior preserves the old path exactly: no normalization metadata, no symbol changes.
* Flag-on behavior normalizes supported bare A-share, US, and HK symbols before loader routing.
* The result includes `_symbol_normalization` metadata and keeps `_data_quality`.
* `get_stock_news`, `get_fund_flow`, `get_research_reports`, Web UI, provider chains, and loaders were not changed.

## 1. Design Goals

The symbol normalizer helper now exists, but it is intentionally not connected to any live tool. The next integration should stay small and reversible.

Goals:

* Let users type natural inputs such as `QQQ`, `600519`, and `00700`.
* Convert those inputs internally to project-standard symbols such as `QQQ.US`, `600519.SH`, and `00700.HK`.
* Preserve already-explicit symbols such as `SPY.US`, `600519.SH`, `300750.SZ`, and `00700.HK`.
* Keep the original Vibe-Trading provider chain unchanged.
* Keep the bottom loader interfaces unchanged.
* Preserve `raw_input` so every normalized call can be audited.
* Record `normalized_symbol` and warnings in tool results or trace data where practical.

## 2. What This Plan Does Not Do

This plan does not approve broad integration.

Out of scope:

* No Chinese company-name resolution.
* No `a-stock-data` integration.
* No yfinance/TLS fix.
* No Web UI rewrite.
* No automatic guessing for low-confidence or ambiguous symbols.
* No override of explicit user suffixes such as `.US`, `.SH`, `.SZ`, `.HK`.
* No provider-chain replacement.
* No trading execution.

## 3. Current Input-To-Tool Path

### Web UI

The Web UI does not currently parse symbols before submission.

Flow:

1. User writes a prompt in `frontend/src/pages/Agent.tsx`.
2. Frontend calls `api.sendMessage(session_id, finalPrompt)` in `frontend/src/lib/api.ts`.
3. Backend stores the user message through `agent/src/session/service.py`.
4. `SessionService` starts `AgentLoop`.
5. `AgentLoop` gives the LLM available tool schemas.
6. The LLM decides which tool to call and what `symbol`, `code`, `ticker`, or `codes` arguments to pass.

Implication:

* The symbol is usually created by the LLM tool call, not by a deterministic frontend parser.
* A low-risk integration point is the tool entrance, where parameters are already structured.

### CLI / API Session Flow

The CLI/API path follows the same core pattern once it enters the session service:

* Prompt is passed as text.
* Agent loop chooses tools.
* Tool arguments are structured JSON generated by the LLM.

Implication:

* A tool-entry normalizer helps Web UI, API, and CLI without changing prompt submission.

## 4. Tool Behavior Findings

### `get_market_data`

File: `agent/src/tools/market_data_tool.py`

Current symbol behavior:

* Accepts `codes`, a list of strings.
* Examples recommend `AAPL.US`, `700.HK`, and crypto symbols.
* Calls `fetch_market_data_json()` in `agent/src/market_data.py`.
* `detect_source()` expects normalized patterns:
  * `AAPL.US` -> `yahoo`
  * `600519.SH` -> `tencent`
  * `00700.HK` -> `yahoo`
* Unknown formats fall through to `tushare`.

Benefit of normalizer:

* Prevents bare `SPY`, `QQQ`, `600519`, or `00700` from being misrouted or unresolved.
* Improves the highest-value data path because many research tasks call OHLCV first.

Risk:

* Ambiguous `000001` could be normalized to `000001.SZ` when the user meant an index.
* A too-broad integration could change behavior for valid non-equity symbols such as `BTC-USDT`.

Recommendation:

* First batch: yes.
* Normalize only equity-like inputs.
* Pass through already-valid symbols and crypto/local symbols unchanged.

Acceptance standard:

* `QQQ` and `QQQ.US` both fetch through the US path.
* `600519` and `600519.SH` both fetch through the A-share path.
* `00700` and `00700.HK` both fetch through the HK path.
* `BTC-USDT`, `local:...`, and explicit valid symbols remain unchanged.
* Tool result includes normalization metadata or at least warnings.

### `get_stock_profile`

File: `agent/src/tools/stock_profile_tool.py`

Current symbol behavior:

* Accepts `ticker`.
* Description says US can be bare or `.US`.
* HK should be zero-padded `.HK`.
* Uses Yahoo quoteSummary path, which has shown TLS/connection-reset issues in local tests.
* Classifies anything not ending in `.HK` as US.

Benefit of normalizer:

* Normalizes `00700` to `00700.HK`.
* Keeps `AAPL` / `AAPL.US` behavior understandable.
* Avoids accidentally treating HK numeric input as US.

Risk:

* This tool is Yahoo profile dependent, and local environment has known Yahoo/yfinance profile instability.
* Connecting normalizer here may make a known provider issue look like a normalizer issue.

Recommendation:

* First batch: cautious yes only after `get_market_data`, or test behind the same feature flag.
* If included, restrict to US/HK and return clear errors for A-share inputs.

Acceptance standard:

* `AAPL` and `AAPL.US` preserve US behavior.
* `00700` becomes `00700.HK`.
* A-share input returns a clear unsupported-market message rather than being treated as US.

### `get_stock_news`

File: `agent/src/tools/stock_news_tool.py`

Current symbol behavior:

* Accepts `code`.
* Requires suffix routing:
  * `.SH/.SZ/.BJ` -> Eastmoney articles.
  * `.US/.HK` -> Yahoo related-instrument matches.
* Bare symbols currently return unsupported-market errors.

Benefit of normalizer:

* `600519` can become `600519.SH`.
* `QQQ` can become `QQQ.US`.
* `00700` can become `00700.HK`.
* Reduces a common Agent failure mode when LLM passes bare codes.

Risk:

* US/HK path returns Yahoo matches, not real news articles.
* For Chinese names, normalizer should not guess; user should use `search_symbol` or future security master.

Recommendation:

* First batch: yes, after or alongside `get_market_data`.
* Keep result wording honest: US/HK returns matches, A-share returns articles.

Acceptance standard:

* `600519` and `600519.SH` both route to Eastmoney A-share news.
* `QQQ` and `QQQ.US` both route to Yahoo matches.
* Chinese names do not silently call a data source.

## 6. Recommended Integration Method

Use a conservative tool-entry adapter.

Recommended behavior:

* Normalize at the tool entry, not inside provider loaders.
* If raw symbol is already explicit and valid, pass it through unchanged.
* If the symbol is crypto, local, or outside the helper's scope, pass through only when the target tool already supports it.
* If normalizer returns invalid, do not call the data provider.
* If normalizer returns `needs_confirmation=True`, do not force a provider call unless the tool context explicitly removes ambiguity.
* Return a clear message such as: `Symbol 000001 is ambiguous; use 000001.SZ for Ping An Bank or provide index context for 000001.SH`.
* Include `raw_input`, `normalized_symbol`, `warnings`, and `needs_confirmation` in the result envelope when possible.
* Add debug logs for normalized results, but never log secrets.
* Do not alter loader interfaces.

Implementation shape for a later approved coding task:

* Add a small shared helper, for example `src.tools.symbol_normalization_support`.
* Keep the pure normalizer in `src.symbols.normalizer`.
* Let each tool decide whether confirmation blocks execution.
* Do not make a central registry wrapper until behavior is proven in a few tools.

## 7. Feature Flag And Rollback Strategy

Recommended environment variable:

```text
VIBE_TRADING_ENABLE_SYMBOL_NORMALIZER=0
```

Recommended default for first integration:

* Default off for the first code integration.
* Enable manually during validation.
* Consider default on only after explicit-symbol regression tests and trading-day checks pass.

Why default off:

* The current project already works with explicit symbols.
* Symbol normalization changes the arguments sent into providers.
* A feature flag gives a clean rollback without reverting code.

Rollback options:

1. Set `VIBE_TRADING_ENABLE_SYMBOL_NORMALIZER=0`.
2. Continue using explicit symbols such as `SPY.US` and `600519.SH`.
3. Revert the integration commit if feature-flag rollback is not enough.

Regression guarantee:

* Explicit symbols must remain valid with the flag on and off.
* Provider fallback order must not change.

## 12. Web UI Bare Symbol Retest Findings

Date: 2026-07-07.

The feature flag was enabled only for local testing:

```bash

```

Results:

| User input | Tool argument observed | Metadata result | Finding |
| -- | -- | -- | -- |
| `600519` | `600519.SH` | `_symbol_normalization` present; `_data_quality` fresh | Compatible, but raw bare input was not observed at the tool boundary. |
| `QQQ` | `QQQ.US` | `_symbol_normalization` present; `_data_quality` stale | Compatible, but `search_symbol` / LLM normalized before `get_market_data`. |
| `00700` | `00700.HK` | `_symbol_normalization` present; `_data_quality` fresh | Compatible, but raw bare input was not observed at the tool boundary. |
| `000001` | `000001.SZ` | ambiguous warning present; `_data_quality` fresh | Not safe enough: the Agent selected the stock before confirmation. |
| `贵州茅台` | `600519.SH` | `_symbol_normalization` present; `_data_quality` fresh | Not safe enough: the Agent guessed the code before the normalizer could ask for confirmation. |

Conclusion:

* The current `get_market_data` integration is compatible with Web UI reports.
* `_data_quality` remains intact.
* The feature flag should remain off by default.
* A tool-entry normalizer is not enough to handle all natural Web UI inputs, because the LLM may rewrite the symbol before calling the tool.

Next design requirement:

* Add a pre-tool symbol intent guard, or change tool contracts so the original user-facing symbol/query is passed into the tool alongside the normalized symbol.
* Ambiguous inputs should not be silently converted in Agent reasoning before confirmation.

## 13. Pre-tool Guard Design Status

Date: 2026-07-08.

Read-only investigation confirmed:

* `AgentLoop.run(user_message=...)` has access to the original user prompt.
* `AgentLoop._process_tool_calls(...)` sees every LLM tool call before execution.
* Tool name and tool args are available before `_execute_single`, `_execute_parallel`, and `_invoke_tool`.
* `_invoke_tool` is the unified final executor, but it currently receives only `tool_name` and `args`.

Recommended guard location:

* First implementation should evaluate tool calls inside `AgentLoop` before provider execution.
* MVP scope should be `get_market_data` only.
* A blocked or clarification decision should append a synthetic tool result instead of calling the provider.

Feature flag:

```text
VIBE_TRADING_ENABLE_PRE_TOOL_SYMBOL_GUARD=0
```

Default remains off.

See:

* `docs_local/PRE_TOOL_SYMBOL_INTENT_GUARD_DESIGN.md`
